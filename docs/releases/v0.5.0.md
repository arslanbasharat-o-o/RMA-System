# Release v0.5.0 — Master Recognition Engine Repair, State Integrity & Architectural Decoupling

**Release Date:** 2026-10-31

## Overview
Release v0.5.0 represents a major architectural milestone for the RMA System. It completely repairs and decouples device hardware identification from warehouse inventory product matching, implements a strict 6-state inventory transition state machine, enforces multi-candidate preponderance consensus over fragile single-result searches, eliminates false legacy iPhone invalidation, and introduces an end-to-end integration test suite verifying real worker pipeline persistence.

## Key Changes & Architectural Improvements

### 1. Separation of Device Model Identification from Warehouse Inventory (DEF-05)
- Decoupled physical phone model recognition (Task A) from internal warehouse catalog association (Task B).
- Fixed the API fallback flaw that previously attached warehouse SKUs and scannable UPC/EAN barcodes to uncataloged external screens matching a model name string.
- Guaranteed that external displays, pending evaluations, and ambiguous candidates strictly retain `barcodeValue = null` and `supplierSku = null`.

### 2. Explicit 6-State Inventory Transition Model (DEF-07)
- Replaced naive binary flags with an explicit state machine:
  - `not_evaluated`: Freshly uploaded item awaiting visual inspection.
  - `processing`: Optical and physical analysis actively running.
  - `matched`: Confirmed warehouse inventory match supported by physical evidence.
  - `no_verified_match`: Evaluation ran to completion, establishing the display is absent from warehouse inventory.
  - `review_required`: Incomplete reference coverage (< 2 reference samples), conflicting cues, or ambiguous candidates requiring human operator adjudication.
  - `error`: Provider timeout, decode failure, or downstream exception.
- Added 8 distinct status badges and clear visual hierarchy in `ItemReviewDrawer.tsx`.
- Added `confirm_inventory` operator review action in `/api/rma-items/[id]/review` for certifying suggestions into confirmed stock.

### 3. Preponderance Consensus & Outlier Defense (DEF-01, DEF-02)
- Replaced fragile `.some()` modern listing checks with true multi-candidate consensus ($\ge 3$ modern listings, $\ge 2:1$ ratio, $\le 1$ legacy outlier).
- Rogue modern retail listings can no longer invalidate legitimate legacy iPhone LCDs (e.g. iPhone 8 Plus).
- Evenly split candidate listings trigger operator review (`model = null, confidence = 0.45`) unless resolved by physical technology markers.

### 4. Hardware Flex-Code & Technology Guards (DEF-03, DEF-06)
- Preserved legacy iPhone form factors against false invalidation: generic Apple `821-` flex cable part number prefixes (e.g. `821-01050-A`) and arbitrary lot stamps (`413022`, `M308`) no longer disqualify legacy models.
- Restricts legacy invalidation exclusively to affirmative physical OLED cues (`HARD`, `SOFT`, `OLED`, `AMOLED`) or aftermarket modern markers (`AL1[2-6]`).

### 5. Cleaner Decision Rejection Ordering & Contradiction Guard (DEF-04)
- Extracted deterministic `evaluateCleanerResponse` interface enforcing strict execution precedence: JSON validation $\rightarrow$ explicit rejection & reasoning contradiction checks $\rightarrow$ candidate rejection handling $\rightarrow$ exact match acceptance $\rightarrow$ provisional adoption $\rightarrow$ abstention.
- Enforced Contradiction Guard: cleaner outputs with `rejected: true` or contradictory reasoning are strictly prevented from bypassing rejection even if the returned model string matches the candidate.

### 6. Real Worker Pipeline Integration & Concurrency Verification (DEF-10)
- Enhanced `processRmaItem()` with deterministic mock inventory match adapters for offline testing.
- Created `src/__tests__/integration/recognition-lifecycle-e2e.test.ts` verifying real worker database persistence across positive, negative, and incomplete comparison flows without manual database update shortcuts.
- Verified stale worker job revision gating (`updateItemForRevision`) preventing older queued background jobs from overwriting human operator corrections.
