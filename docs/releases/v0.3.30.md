# v0.3.30: two-reference acceptance override

A comparison against two independent verified references is now strong enough
to accept the selected model even when the comparator keeps a residual caveat
about a lookalike it already weighed and ruled out. Previously that caveat
suppressed an otherwise correct, high-confidence result and left the item with
no model suggestion.

The change is deliberately narrow:

- Two independent references plus a score at or above 0.93 can accept the
  selected model with a residual `unresolvedAlternatives` note.
- One reference still requires independent search corroboration and an empty
  alternative list.
- Scores below 0.93 are never accepted by this path.
- Human review still applies to construction conflicts and every result that
  does not meet the acceptance policy.

This follows the live v0.3.29 test on the user's iPhone 11 photo. The visual
search identified iPhone 11 at 0.97, and the verified-photo comparator selected
the same catalog model at 0.93 with two supporting references. The item still
received no model because the comparison reported a residual iPhone XS Max
caveat. The acceptance policy, not the comparison, was the blocker.

Focused recognition tests, typecheck, and lint pass before deployment. The
release is built and deployed directly to production outside the GitHub CI/CD
workflow at the user's request; the frozen holdout and live evidence are kept
on the server for review.
