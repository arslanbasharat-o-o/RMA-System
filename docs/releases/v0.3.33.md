# v0.3.33: don't let an unrepresented search label veto a match

The comparator no longer returns `none` merely because image search found a
lower-ranked model that has no verified reference photo. It now selects the
best-supported supplied candidate, records the unrepresented label as a caveat,
and leaves acceptance to the normal policy.

This fixes the remaining iPhone 11 failure. On v0.3.32 discovery selected iPhone
11 at 0.86, but the focused comparison returned `none` at confidence 0.30. Its
only reason was that iPhone XS Max appeared in search results without a verified
reference. The references and the upload clearly agreed on the stepped left-side
flex routing and outward cable exit.

The earlier wording caused the same problem in two ways:

- it told the model to return `none` when an unrepresented alternative could not
  be distinguished;
- it described every unrepresented label as an equal evidence-backed
  alternative, even when search had ranked it far below the winner.

With the revised prompt, the identical five-reference comparison selected iPhone
11 in three consecutive attempts at 0.94, citing both independent iPhone 11
references. The only residual caveat was iPhone XR, whose supplied reference
actually differs in flex routing.

Acceptance rules are unchanged:

- score at least 0.93;
- two independent verified references for the selected catalog ID;
- the selected ID is in the candidate set;
- construction conflicts and unresolved competing models still need human
  review.

This is a change to how the comparator reports uncertainty, not a lower
threshold and not an auto-verification path. The release is deployed directly to
production outside GitHub CI/CD at the user's request.
