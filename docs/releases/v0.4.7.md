# v0.4.7: Catalog Foreign Key Fix, Worker Processing Resilience, and AI Vision Guidance

## What changed

- **Catalog Foreign Key Constraint Fix**: Historical manual review actions retained obsolete `catalogDisplayId` values from before the display catalog was deprecated. When recognition was re-run on previously reviewed items, spreading the manual override attempted to write orphaned UUIDs to `rma_items.catalog_display_id`, violating foreign key constraint `rma_items_catalog_display_fk`. `processor.ts` now sanitizes `catalogDisplayId` against `allCatalog` before updating `rma_items`, and only evaluates catalog presence constraints when `allCatalog` has active records.
- **Worker Processing Hang Resilience**: Jobs encountering unhandled exceptions during background processing previously left items indefinitely stuck in `status: "processing"`. Added a resilience catch handler in `src/worker/index.ts` that safely transitions crashed items from `processing` to `review_required` with diagnostic error notes so operators can inspect and resolve them.
- **AI Vision Candidate Guidance**: When Google Lens search returns low-confidence or noisy candidates (< 0.85), physical display inspection from OpenAI Vision (GPT-4o) now populates `suggestedModel` and `displayName` for human operator review even if the exact model string was missing from third-party listing titles, preventing incorrect fallback suggestions.
