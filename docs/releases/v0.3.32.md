# v0.3.32: focused fallback when discovery abstains

Discovery now has a safe fallback. If every verified-library discovery batch
returns `none`, the comparator runs one focused comparison against the three
closest search-ranked models instead of returning no model immediately.

This fixes the repeated iPhone 11 failure. On v0.3.31 the visual search still
ranked iPhone 11 first at 0.97, but all four discovery batches abstained. The
function returned before the focused finalist comparison could run, so the item
was reported as unidentified even though the focused comparison had selected
iPhone 11 at 0.93-0.94 in three consecutive probes.

The fallback is not an auto-verification path:

- the model must still score at least 0.93;
- two independent verified references must support the selected catalog ID;
- the selected ID must be in the supplied candidate set;
- construction conflicts and unresolved competing models still require human
  review;
- a discovery batch error still aborts the result instead of falling back.

If discovery returns a winner, the v0.3.31 behavior is unchanged: the winner is
rechecked with both examples against its two closest search-ranked alternatives.
The fallback only replaces the empty-winner return path.

This release is built and deployed directly to production outside GitHub CI/CD
at the user's request. Temporary smoke-test records are removed after the live
replay.
