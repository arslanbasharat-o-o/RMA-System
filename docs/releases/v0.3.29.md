# v0.3.29 candidate: verified-library discovery

Verified displays can nominate a device model even when visual search omits it.
The worker discovers candidates across verified catalog labels, then compares
finalists using detailed photos and distinct reference items. OCR part-number
feedback and manual verification safeguards remain part of the final decision.

The separate `OPENAI_REFERENCE_MODEL` role was probed on the server with GPT-6.1
Sol. The supplied tuning photo selected the correct iPhone 13 Pro Max catalog
model at 0.95 with two independent supporting references; this score is not a
calibrated probability. The comparison also reported a construction difference,
so human review remains required.

Frozen holdout hash: `b766a1d73ab5e7d0ae4fff1324962418d2646c7b780a9056c59abb2121f3b99c`.
Twelve catalog labels with independent verified items are eligible. Evaluation
excludes each source item and checksum, keeps target labels outside prompts,
and makes no production database or storage changes. On the frozen holdout the
comparator selected the exact model on 8 of 12 photos (66.7%), accepted 2 of 12
(16.7%) with 100% precision, and produced no confident false matches. The
missing-reference set returned no accepted model on all 4 photos. Median
comparison latency was about 70 seconds (p95 about 98 seconds). The acceptance
policy deliberately withholds single-reference or ambiguous results for human
review.

A live authenticated production upload of the supplied photo returned Apple
iPhone 13 Pro Max at 0.94, compared against 32 verified reference displays. The
item remained in review required because lower-board construction and connector
details differed from the references; it was not auto-verified. The temporary
customer, RMA, item, images, and session were removed after the check.

This is immediate reference learning from operator labels, not model-weight
fine-tuning. The candidate is built for direct server deployment; GitHub CI/CD
publication follows the user's final release instructions.
