# v0.3.34: decisive single-reference comparison stays visible in review

> **Superseded by v0.4.0.** This version was built but never deployed. Its
> single-reference exception and the model-level corroboration work are
> consolidated into v0.4.0, which is the release verified in production.

A comparison against one operator-verified reference can now set the suggested
model when it is decisive: confidence at least 0.97, at least three concrete
matching cues, and no unresolved alternative. The item still requires human
review and is never auto-verified.

This is a narrow exception for near-identical siblings. On v0.3.33 the live
replay selected **iPhone XR at 0.98** from the single verified XR reference. It
reported four matching cue groups, no unresolved alternatives, and one
non-blocking caveat about folded flex ends. The operator confirmed that iPhone XR
is the correct display. The existing policy withheld the result because one
reference without search agreement was not enough, while generic image search
ranked the visually similar iPhone 11 first.

The verified reference is the stronger signal here. iPhone XR and iPhone 11
assemblies share enough geometry that search can prefer the wrong sibling, and
the reference comparison is the component built specifically to resolve that.
Requiring a second XR reference before showing the result would leave this
operator-confirmed case unidentified; weakening the two-reference rule globally
would be worse.

The exception is deliberately constrained:

- exactly one supporting reference is allowed, and only at 0.97 or above;
- at least three concrete matching cues must be reported;
- any unresolved alternative blocks it;
- the selected catalog ID must be in the supplied candidate set;
- a comparison that is applied still goes through the normal item status path,
  and conflicting cues keep the item in `review_required`.

The base threshold remains 0.93, and two independent references remain the
standard for accepting a match that still has unresolved alternatives or for
overriding a prior caveat. Part-number learning still requires two independent
verified items.

An earlier v0.3.34 candidate would have done the opposite: keep the iPhone 11
search suggestion and record the one-reference XR result as a caveat. It was
built but never deployed. That behavior conflicts with the confirmed ground
truth and was discarded.

This candidate was not deployed, as noted above; v0.4.0 superseded it.
