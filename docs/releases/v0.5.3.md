# RMA System v0.5.3 — Multi-Image Vision Corroboration, Mandatory Front/Back Camera Workflow & Server Optimization

Release Date: 2026-10-31
Target Infrastructure: Production KVM2 VPS (`rma.txparts.io`)
Runtime: Node.js 24 / Next.js 16 / PostgreSQL 16 / Docker Compose

## Executive Summary

Release `v0.5.3` delivers full physical display disambiguation across multiple angles, implements the mandatory Front + Back camera intake workflow, and hardens recognition pipeline reliability:

1. **Mandatory Front & Back Camera Intake Workflow**:
   - Front view: Mandatory (exposes bezel symmetry, notch, Dynamic Island, and top speaker cutout).
   - Back view: Mandatory (exposes shield plate, flex cable routing, connectors, stamps, and hardware layout).
   - Flex cable close-up: Optional (enhances OCR and part-number identification when present).
   - Additional photographs: Optional (captures stamps, stickers, and markings).
   - Progression guard: Operators cannot advance to next display or submit recognition without both Front and Back photos.
   - Server-side guard: Backend validation strictly prevents queue publication and API bypass attempts when required angles are missing, while gracefully preserving older historical RMA records.

2. **Multi-Image Vision Corroboration**:
   - Extended OpenAI visual cleaner to accept all captured display perspectives (Front, Back, and Flex close-up) with descriptive angle prompts.
   - Prioritized Back view for Google Lens visual search to match structural hardware features rather than featureless front glass.
   - Extended visual cleaner timeout from 12s to 45s (`LENS_TIMEOUT_MS`) to accommodate deep reasoning passes (`gpt-5.6-terra`).

3. **Warehouse Variant Model Consensus**:
   - When seeded inventory comparison is ambiguous between warehouse SKU variants (e.g., Hard OLED vs AM) of the same phone model, the engine extracts the shared consensus device model and flags `review_required` rather than discarding the known phone model.

4. **Cleaner Provider Error Guard**:
   - In `synthesizer.ts`, guarded `safeDetectedAssembly` to prevent uncorroborated candidate names from populating `predictedDisplayAssembly` on cleaner provider errors.
